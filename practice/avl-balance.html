Keeping the Tree Short↗

개념 확인: AVL Balance

균형 인수로 기울어진 자리를 찾고 AVL 조건이 높이를 묶는 이유를 계산한다.

문제 1

균형 인수 계산

문제 1과 2는 빈 BST에 40, 20, 60, 10, 30, 70, 5를 차례로 넣은 트리 40(20(10(5, -), 30), 60(-, 70))을 쓴다. 균형 인수는 bf(v) = h(왼쪽) − h(오른쪽)이고 빈 부분 트리의 높이는 −1이다.

  1. 노드 5, 10, 20, 30, 40, 60, 70의 높이와 균형 인수를 적는다.
  2. 이 트리가 AVL 트리인지 판정한다.
  3. 균형 인수가 양수인 노드와 음수인 노드가 각각 어느 쪽으로 기울었는지 적는다.
  4. 단말 노드의 균형 인수가 0인 이유를 적는다.
해설 펼치기
  1. 5: 높이 0, bf 0. 10: 1, bf 0 − (−1) = 1. 20: 2, bf 1 − 0 = 1. 30: 0, bf 0. 40: 3, bf 2 − 1 = 1. 60: 1, bf −1 − 0 = −1. 70: 0, bf 0.
  2. AVL 트리다. 모든 노드의 |bf|가 1 이하다.
  3. bf가 양수인 10, 20, 40은 왼쪽 부분 트리가 더 높아 왼쪽이 무거움, 음수인 60은 오른쪽 부분 트리가 더 높아 오른쪽이 무거움이다.
  4. 두 부분 트리가 모두 비어 높이가 −1로 같기 때문이다.
문제 2

삽입 뒤 올라가며 확인하기

문제 1의 원래 BST와 균형 인수 정의를 쓴다.

1의 트리에서 각각 따로 키를 하나 넣는다.

  1. 키 3을 넣을 때 균형 인수를 고쳐야 하는 노드와 갱신 뒤의 값을 적는다.
  2. 3을 넣은 뒤 |bf| = 2가 된 노드를 모두 적고, 재균형을 시작할 노드를 고른다.
  3. 키 25를 넣을 때 20에서 갱신이 멈추는 이유를 적는다.
  4. 삽입 경로 밖의 노드를 확인하지 않아도 되는 이유와 이 확인의 비용을 적는다.
해설 펼치기
  1. 3의 부모 5부터 올라가며 고친다. 5는 0 → 1이 되어 위로 가고, 10은 1 → 2가 된다. |bf| = 2인 10에서 재균형하고 멈추므로 경로 위의 20과 40에 저장된 값은 고치지 않는다.
  2. 높이로 다시 세면 10, 20, 40이 모두 |bf| = 2다. 새 값에서 가장 가까운 10에서 재균형을 시작한다. 그 아래는 아직 AVL 조건을 지키고, 10을 고치면 그 부분 트리가 삽입 전 높이로 돌아가 20과 40도 다시 조건을 지킨다.
  3. 25는 30의 왼쪽에 붙어 30은 bf 1이 되지만 20은 1 − 1 = 0이 된다. 0이 되면 20의 높이가 늘지 않았으므로 그 위는 바뀌지 않는다.
  4. 부분 트리 높이가 바뀔 수 있는 노드는 새 단말 노드의 조상뿐이다. 한 노드 확인이 O(1)이고 높이만큼 올라가므로 O(log n)이다.
문제 3

가장 성긴 AVL 트리

  1. N(h) = N(h − 1) + N(h − 2) + 1, N(0) = 1, N(1) = 2일 때 N(2)부터 N(9)까지 구한다.
  2. 노드 100개를 담은 AVL 트리의 높이가 될 수 있는 최댓값을 구한다.
  3. 같은 100개를 가장 균형 있게 담은 트리의 높이와 비교한다.
  4. N(h)가 높이에 대해 지수적으로 늘어나는 것이 탐색 비용에 주는 의미를 적는다.
해설 펼치기
  1. 4, 7, 12, 20, 33, 54, 88, 143이다.
  2. N(8) = 88 ≤ 100 < N(9) = 143이므로 높이 9에는 최소 143개가 필요하다. 최대 높이는 8이다.
  3. ⌊log₂ 100⌋ = 6이다. AVL 최대 높이 8은 상수 배(약 1.44배) 안쪽이다.
  4. n개를 담은 AVL 트리의 높이가 O(log n)으로 묶이므로 탐색·삽입·삭제의 최악 비용도 O(log n)이다.
문제 4

균형 조건이 요구하는 것

다음 문장이 맞는지 판단하고 틀리면 고친다.

  1. AVL 트리는 모든 노드에서 좌우 부분 트리의 높이가 정확히 같아야 한다.
  2. 정렬된 값을 보통 BST에 넣으면 높이가 n − 1이 될 수 있어, 입력을 섞을 수 없으면 삽입할 때 균형을 유지해야 한다.
  3. 노드마다 높이나 균형 인수를 저장하지 않아도 균형 확인은 O(1)이다.
  4. AVL 트리는 BST의 ordering invariant 대신 높이 균형을 지키는 트리다.
해설 펼치기
  1. 틀렸다. 높이 차이가 1 이하면 된다. 모든 노드에서 차이가 0이면 n = 2^(h+1) − 1인 경우만 가능하다.
  2. 맞다.
  3. 틀렸다. 저장하지 않으면 부분 트리 전체를 봐야 한다. 저장하면 O(1)이다.
  4. 틀렸다. ordering invariant에 높이 균형을 더해 두 조건을 모두 지킨다.
문제 5

높이 차이가 만드는 비용

  1. 노드 1,000개와 1,000,000개일 때 AVL 트리 높이 상계와 편향 BST의 높이를 적는다.
  2. 두 경우 탐색의 최악 비교 횟수 차이를 설명한다.
  3. 균형 트리가 보통 BST보다 삽입에서 추가로 하는 일을 적는다.
해설 펼치기
  1. 1,000개: AVL 높이 상계 약 1.44 log₂ n ≈ 14(문제 3의 N(h)로 구한 정확한 최대 높이는 13), 편향 BST 999. 1,000,000개: AVL 상계 약 28(정확한 최대 높이 27), 편향 BST 999,999다.
  2. 탐색은 높이만큼 비교하므로 AVL은 수십 번 안쪽, 편향 BST는 원소 수에 비례한다.
  3. 노드마다 균형 정보를 저장하고, 삽입 뒤 자리 찾기에 더해 균형 정보 갱신과 재균형을 한다.
