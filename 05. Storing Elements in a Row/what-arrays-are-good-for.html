Storing Elements in a Row

What Arrays Are Good For

한 배열에 서로 다른 작업을 차례로 쌓으면 인덱스 접근과 끝 추가의 작은 비용, 가운데 삽입과 삭제의 이동 비용이 같은 기록에서 드러난다.

인덱스 접근주소 계산 뒤 한 칸을 읽어 Θ(1)이다.
끝 추가내부 배열에 빈 칸이 있으면 이동 없이 한 칸을 쓴다.
가운데 변경위치 i부터 뒤쪽 원소를 옮기므로 최악의 경우 Θ(n)이다.

get은 한 칸에 도달하고 삽입·삭제는 뒤쪽 원소 수만큼 옮긴다

모든 연산은 같은 배열 상태에서 이어진다. 실행 직후 바뀐 칸과 이동한 칸, 정확한 작업 수가 함께 기록된다.

get은 배열 길이와 무관하게 한 칸에 도달한다. 삽입은 a[i]부터 끝까지의 원소 수, 삭제는 a[i] 뒤의 원소 수가 이동 수다.

연산마다 작업 수가 실행 당시의 n과 i로 정해진다

위 절의 배열 상태와 실행 기록을 그대로 쓴다. 각 행은 실행 당시 n과 i로 계산한 작업 수를 보존한다.
